# too many apples · 사과 쟁탈전

닉네임과 초대 링크로 참여하는 PC 마우스 전용 1~8인 사과 게임입니다.

## 실행

Node.js 22.13 이상(권장 24 LTS)이 필요합니다.

```sh
npm ci
npm run db:local
npm run dev
```

화면에 표시되는 로컬 주소를 엽니다. 두 개의 서로 다른 브라우저 세션에서 테스트할 수 있습니다. 브라우저 탭별 참가 토큰은 `sessionStorage`에 보관되어 새로고침해도 복귀합니다. 초대 링크는 같은 서버에 접속할 수 있는 참가자에게 공유해야 합니다. `localhost` 링크는 다른 PC에서 접속할 수 없으므로 외부 이용에는 서버 배포가 필요합니다.

## 게임

- 가입 없이 1~12자 닉네임으로 방 생성 또는 초대 링크 입장
- 방장만 1~8명의 접속 참가자로 시작, 3초 카운트다운 후 120초 경기
- 모든 참가자에게 같은 17×10 숫자 배치, 각자의 보드는 독립적
- 마우스 왼쪽 버튼으로 사각형 선택. 남아 있는 숫자의 합이 10이면 제거
- 이미 비워진 칸은 합과 점수에서 제외, 제거한 사과 1개당 1점
- 서버 시간이 기준이며 시작 전과 종료 후 선택 및 이전 라운드 선택은 거절
- 점수/상태는 500ms 간격 폴링. 실제 갱신 시간은 네트워크 지연에 따라 달라짐
- 동점은 공동 순위(예: 1, 1, 3위), 재경기는 새 동일 보드로 점수 초기화
- 30초 이상 응답 없는 참가자는 오프라인 처리. 방장 이탈 시 온라인 참가자로 승계
- 경기 중 신규 입장 불가, 기존 참가자는 새로고침 후 복귀 가능
- 방은 생성 후 24시간 만료. 서버에 참가자 상태와 점수를 저장

## 구조

Vinext/React UI와 Cloudflare Worker API, D1 데이터베이스를 사용합니다. 방 상태를 버전 비교 후 원자적으로 갱신해 동시 입장과 득점 요청의 충돌을 처리합니다. 점수/사과 제거는 서버에서 계산하며, 클라이언트에는 자기 보드와 공개 순위만 전달합니다. 참가 토큰은 응답에 노출하지 않습니다.

`game/engine.ts`: 규칙과 공개 상태 생성. `game/repository.ts`: D1 저장과 동시성 제어. `app/api/rooms`: 생성/참가/상태/선택 API. `game/board.tsx`: 드래그 조작. `game/use-game.ts`: 연결 및 재접속.

## 검증

```sh
npm test
npm run typecheck
npm run build
# 로컬 DB와 개발 서버 실행 후
npm run test:integration
```

단위 테스트는 시간 경계, 공동 순위, 재경기, 이탈, 입력 검증을 포함합니다. API 통합 테스트는 실제 동시 입장, 8명 제한, 시작 동기화, 보드 독립성, 중복 득점 차단, 점수 전파와 방장 승계를 검증합니다.

새 스키마 변경은 `npm run db:generate`로 마이그레이션을 추가합니다. 로컬 적용은 `npm run db:local`을 사용합니다. Sites 배포는 `.openai/hosting.json`의 D1 바인딩과 저장된 마이그레이션을 사용합니다. 외부 초대 이용에는 사이트 접근 권한도 참가자가 접근 가능하도록 설정되어야 합니다.

WebMCP를 지원하는 브라우저에서는 `enter_apple_room` 도구로 동일한 입장 흐름을 실행할 수 있습니다. 미지원 브라우저에서는 일반 UI를 사용합니다.

현재 검증은 게임 규칙 단위 테스트, 실제 HTTP API 통합 테스트, TypeScript 검사와 프로덕션 빌드까지 수행했습니다. 마우스 UI의 브라우저 자동화 테스트와 실제 WebMCP 브라우저 컨텍스트 검증은 수행하지 않았습니다.
